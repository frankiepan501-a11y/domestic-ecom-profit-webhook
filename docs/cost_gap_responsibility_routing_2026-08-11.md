# 国内电商毛利成本缺口责任分流修复记录

## 问题

2026-07 试算把 3 个天猫宝空订单号作为“SKU/对象”发给采购，要求维护采购成本。消息缺少平台、店铺、对象类型、商品、真实原因和责任判断。

## 根因

- `settlement_engine` 已生成完整缺口行，但 `task_runner` 只抽取对象列。
- 订单资料缺口与 ERP SKU 成本为 0 共用同一个采购通知。
- 订单号再按 SKU 元数据查询，导致名称和店铺为空。
- 3 个目标订单在 2026-05 下单、2026-07 结算；已上传订单明细从 2026-06-01 才开始，因此订单完全未匹配。

## 改动

- 新增 `app/cost_gap_alert.py`：按确定性规则分类、补充订单上下文、分别发送运营/采购卡；责任不明时只发 Frankie。
- 新增 `cards.cost_gap_alert_card()`：运营、采购、待判断三类卡使用不同结论、字段、步骤和处理入口。
- `task_runner` 改为把完整 `settlement + raw` 交给分流器，不再发送旧纯文本采购告警。
- 新增 `COST_GAP_ALERT_FRANKIE_ONLY`，默认 `true`，避免样卡误发业务同事。
- `/health` 增加 `cost_gap_responsibility_routing` 和 `cost_gap_alert_frankie_only`。
- 订单明细未匹配类 P0 也进入运营分流，不再只处理“采购成本”类别。
- 采购分流同时校验 `cost_rows` 中存在同名 ERP SKU 且单件采购成本确为 0；只有问题文案、没有 SKU 证据时留给 Frankie。
- Frankie-only 与正式生产使用不同幂等键；发送未取得 message_id 时不记为已发送，可安全重试。
- 单路缺口超过 25 条时自动分页，每张卡都显示总数/页码；补导范围按全部缺口计算。
- 每条明细直接写平台/店铺；抖音/小红书结算源有下单日期时自动取值，没有时按结算月向前保守回溯 3 个月。
- 采购发送按每名收件人单独防重复；岗位无人时给 Frankie 的兜底提醒不会阻断岗位恢复后的正式派送，部分人员发送失败也只重试失败者。
- 运营群、单个采购收件人或待判断私聊发生网络异常时按路由隔离，不会让后续收件人和其他责任路由一起漏发；失败项不写已发送审计。
- 防重复记录查询发生异常时，为避免重复打扰，只跳过当前这一张卡并记录告警；后续页面、收件人和其他责任路线继续处理。
